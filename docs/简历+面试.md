## 二、面试问答

### 2.1 项目概述与架构

**Q1：请介绍一下你参与的情绪小站项目？**  
A：情绪小站是一款专注于情绪管理与疗愈的微信小程序，主要功能包括：情绪日记记录（支持5种情绪标签）、情绪分享社区（帖子发布、点赞、评论、转发）、情绪周边商城（商品浏览、购物车、下单支付）、音乐疗愈、留言板与抱抱等。项目采用前后端分离架构，用户端是微信小程序，管理端是Vue 3 Web应用，后端是Spring Boot服务，数据库使用MySQL 8.0。

**Q2：项目的技术架构是怎样的？**  
A：整体采用前后端分离架构：  
- 用户端：微信小程序原生开发（WXML + WXSS + JavaScript），28个页面，4个TabBar  
- 管理端前端：Vue 3 + Element Plus + Vite，8个管理页面  
- 小程序后端：Spring Boot 2.7 + MyBatis + JWT，14个Controller，20个Mapper  
- 管理端后端：Spring Boot 2.7 + MyBatis + JWT，9个Controller，10个Mapper  
- 数据库：MySQL 8.0，20+张数据表  

**Q3：项目中有哪些安全机制？**  
A：主要安全机制包括：  
1. JWT认证：用户登录后获取Token，后续请求需在Header中携带 `Authorization: Bearer <token>`  
2. JWT拦截器：自动校验Token有效性，无效或过期返回401状态码  
3. 参数校验：后端对接口参数进行校验，防止非法数据进入系统  
4. 全局异常处理：统一捕获并处理异常，避免敏感信息泄露  
5. 文件上传限制：限制文件类型（JPG/PNG/WEBP）和大小（≤2MB）

### 2.2 核心功能与业务逻辑

**Q4：用户登录是如何实现的？**  
A：用户通过微信登录获取code，将code、昵称、头像URL发送到后端 `/api/user/login` 接口。后端使用code换取openid（当前为Mock实现），查询用户是否已存在：存在则直接返回JWT Token；不存在则创建新用户后返回Token。Token有效期为1小时，过期后需重新登录。

**Q5：日记功能的核心流程是怎样的？**  
A：用户在首页或日记编辑页选择情绪标签（开心、难过、生气、平静、焦虑），填写标题和内容，可选添加图片和设置公开状态。保存时调用 `/api/diary` 接口（POST新增/PUT编辑），首次发布获得2个心动币（每日限一次）。日记支持软删除，删除后进入回收站可恢复。

**Q6：订单状态流转是怎样的？**  
A：订单状态流转如下：  
`pending(待发货) → shipped(已发货) → signed(已签收) → completed(已完成)`  
待发货状态可取消订单（心动币退回、库存恢复）；已发货状态可申请退款（需管理端审核）；快递状态为已签收时用户可确认收货。

**Q7：心动币激励体系是怎样设计的？**  
A：心动币是平台虚拟货币，共有8种获取途径：注册赠送、每日登录、发布日记、发布帖子、转发日记、点赞、评论、确认收货。每种奖励都有每日次数限制，通过 `daily_reward` 表记录每日领取情况，防止重复领取。

**Q8：帖子申诉机制是怎样的？**  
A：用户可删除自己的帖子（进入回收站），被管理员删除的帖子可申诉。申诉后状态变为"申诉中"，管理端审核：通过则帖子恢复，不通过则仅保留彻底删除功能。申诉状态通过 `appeal_status` 字段管理（0-未申诉，1-申诉中，2-申诉通过，3-申诉不通过）。

### 2.3 数据库设计

**Q9：项目中有哪些核心数据表？**  
A：核心数据表包括：  
- `user`：用户表（id, openid, nickname, coin_balance）  
- `diary`：日记表（id, user_id, emotion, title, content, is_public）  
- `post`：帖子表（id, user_id, content, like_count, comment_count, source）  
- `product`：商品表（id, name, price, stock, is_on_sale）  
- `order`：订单表（id, user_id, order_no, total_amount, status）  
- `address`：收货地址表（id, user_id, name, phone, province, city, detail）  
- `notification`：通知表（id, user_id, type, title, content）  
- `banner`：轮播图表（id, title, image_url, link_url, sort_order）  

**Q10：订单创建时涉及哪些数据库操作？如何保证数据一致性？**  
A：订单创建涉及以下操作：  
1. 查询购物车商品信息  
2. 校验用户心动币余额是否充足  
3. 校验商品库存是否充足  
4. 扣减用户心动币余额  
5. 扣减商品库存  
6. 生成订单记录  
7. 生成订单明细记录  
8. 清空购物车  

通过Spring事务管理保证数据一致性，使用 `@Transactional` 注解，任意步骤失败则回滚所有操作。

**Q11：删除用户时需要注意什么？**  
A：删除用户时需要处理外键约束，需先删除相关数据：订单、收货地址、帖子、评论、点赞记录、购物车、留言等，否则会触发外键约束错误。项目中在 `AdminUserService` 中实现了级联删除逻辑。

1. 检查前端传递的规格参数是否正确

### 2.5 问题解决与优化

**Q20：项目中遇到的最大挑战是什么？如何解决的？**  
A：最大挑战是订单创建的事务一致性问题。在高并发场景下，可能出现超卖或余额不足但订单创建成功的情况。解决方案：  
1. 使用数据库事务保证操作的原子性  
2. 在扣减库存前加锁，防止并发超卖  
3. 使用乐观锁或悲观锁控制并发访问  
4. 在Service层添加业务校验，确保余额和库存充足  

**Q21：如何优化小程序的性能？**  
A：小程序性能优化措施：  
1. 图片优化：压缩图片大小，使用WebP格式，懒加载图片  
2. 代码分包：将非首页代码分包，减少主包体积  
3. 请求优化：合并请求，使用缓存，减少网络请求次数  
4. 渲染优化：使用虚拟列表，减少DOM节点数量  
5. 数据缓存：使用wx.setStorage缓存用户信息、Token等数据  
6. 异步加载：将非关键资源异步加载，提升首屏加载速度  

**Q22：如果让你优化项目，你会从哪些方面入手？**  
A：优化方向：  
1. 添加分页功能：帖子列表和商品列表目前没有分页，数据量大时影响性能  
2. 引入Redis缓存：缓存热门商品、轮播图、用户信息等，减少数据库查询  
3. 接入WebSocket：实现实时聊天功能，提升社区互动体验  
4. 添加内容审核：接入文本审核API，过滤敏感词和违规内容  
5. 接入快递API：自动查询物流状态，减少管理员手动操作  
6. 增加单元测试：为核心业务逻辑编写单元测试，提升代码质量

### 2.6 管理端相关

**Q23：管理端如何实现管理员认证？**  
A：管理端使用独立的JWT认证体系：  
1. 管理员通过 `/api/admin/login` 接口登录，传入用户名和密码  
2. 后端验证用户名密码，正确则生成JWT Token返回  
3. 管理端前端将Token存储在localStorage中  
4. 路由守卫检查Token，未登录跳转登录页  
5. 管理端后端使用 `AdminJwtInterceptor` 拦截器校验Token  

**Q24：管理端添加商品后，小程序如何实时显示？**  
A：小程序端在商品列表页加载时调用 `/api/product/list` 接口获取商品数据，管理端添加商品后数据实时写入数据库，小程序刷新页面即可看到新商品。如需实现真正的实时更新，可考虑使用WebSocket推送或轮询机制。

**Q25：管理端如何处理订单退款审核？**  
A：退款审核流程：  
1. 用户在订单详情页点击"申请退款"，填写退款原因  
2. 后端创建退款申请记录，订单状态变为"退款审核中"  
3. 管理端订单管理页面显示待审核退款申请（带小红点提示）  
4. 管理员点击审核，可选择"同意退款"或"拒绝"  
5. 同意退款：心动币退回用户，库存恢复，订单状态改为"已退款"  
6. 拒绝：订单状态不变，用户可再次申请

### 2.7 小程序特性相关

**Q26：首页昵称旁边的手掌挥手动画是如何实现的？**  
A：使用CSS动画实现：  
```css
.wave-icon {
  animation: wave 2s ease-in-out infinite;
  transform-origin: 70% 70%;
}
@keyframes wave {
  0%, 100% { transform: rotate(0deg); }
  10% { transform: rotate(14deg); }
  20% { transform: rotate(-8deg); }
  30% { transform: rotate(14deg); }
  40% { transform: rotate(-4deg); }
  50% { transform: rotate(10deg); }
  60% { transform: rotate(0deg); }
}
```
通过 `@keyframes` 定义旋转角度变化，`transform-origin` 设置旋转中心点，`animation` 属性应用动画效果。

**Q27：今日锦囊翻转卡片是如何实现的？**  
A：使用CSS 3D变换实现：  
1. 设置容器 `perspective` 属性，创建3D空间  
2. 设置卡片容器 `transform-style: preserve-3d`  
3. 正面和背面分别设置 `backface-visibility: hidden`  
4. 背面初始状态 `transform: rotateY(180deg)`  
5. 点击时切换容器的 `transform: rotateY(180deg)`  

**Q28：小程序如何处理图片上传？**  
A：图片上传流程：  
1. 使用 `wx.chooseMedia` 或 `wx.chooseImage` 选择图片  
2. 使用 `wx.uploadFile` 将图片上传到后端 `/api/upload` 接口  
3. 后端校验文件类型（JPG/PNG/WEBP）和大小（≤2MB）  
4. 保存图片到服务器指定目录，返回图片URL  
5. 前端将URL存入表单数据，提交时一并发送

## 三、项目亮点总结

### 技术亮点
1. **JWT认证体系**：实现用户端和管理端两套独立的JWT认证，保障接口安全
