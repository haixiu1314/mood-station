# 情绪小站 — 答辩问答文档

---

## 一、项目概述类问题

### Q1：你的项目是做什么的？解决了什么问题？

**答：** 情绪小站是一个微信小程序，主要解决现代人情绪无处表达、缺乏情绪管理工具的问题。用户可以写日记记录心情、在社区分享情绪、购买治愈商品、听音乐、和其他用户互动（留言、抱抱）。同时有管理端后台，管理员可以管理用户、商品、订单、帖子等内容。

---

### Q2：你的系统有哪些角色？

**答：** 两个角色：
- **普通用户**：使用小程序端，可以写日记、发帖、购物、听音乐等
- **管理员**：使用管理端网页后台，管理用户、商品、订单、帖子等

---

### Q3：项目用了什么技术栈？

**答：** 分四个部分：

| 部分 | 技术 |
|------|------|
| 小程序前端 | 微信小程序原生开发（WXML + WXSS + JS） |
| 小程序后端 | Spring Boot 2.7 + MyBatis + MySQL + JWT |
| 管理端前端 | Vue 3 + Element Plus + Vite + Axios |
| 管理端后端 | Spring Boot 2.7 + MyBatis + MySQL + JWT |

---

### Q4：前后端是怎么通信的？

**答：** 通过 HTTP 请求通信。前端用 `wx.request`（小程序）或 `axios`（管理端）发送请求，后端用 Controller 接收请求，处理完后返回 JSON 格式数据。所有接口统一返回格式：`{ code: 200, message: "success", data: {...} }`。

## 二、技术实现类问题

### Q5：用户登录是怎么实现的？

**答：** 支持两种登录方式：
1. **微信登录**：前端调用 `wx.login` 获取 code，传给后端，后端用 code 换取 openid（当前是 Mock 实现），自动注册或登录，返回 JWT Token
2. **账号密码登录**：前端传 username 和 password，后端验证后返回 JWT Token

Token 存在小程序的 `wx.setStorageSync` 或管理端的 `localStorage` 中，每次请求放在请求头 `Authorization: Bearer xxx` 里。

---

### Q6：JWT 是什么？怎么工作的？

**答：** JWT（JSON Web Token）是一种无状态的认证方式。流程是：
1. 用户登录成功，后端用 `JwtUtil` 生成 Token，里面包含 userId 和 openid
2. Token 返回给前端，前端存起来
3. 每次请求前端把 Token 放在请求头里
4. 后端 `JwtInterceptor` 拦截器拦截每个请求，解析 Token，验证是否过期
5. 验证通过就把 userId 放到 request 属性里，Controller 用 `@RequestAttribute("userId")` 获取

Token 快过期时，拦截器会自动刷新 Token，通过响应头返回新 Token。

---

### Q7：拦截器是怎么配置的？哪些接口不需要登录？

**答：** 在 `WebMvcConfig.java` 中配置：
```java
registry.addInterceptor(jwtInterceptor)
    .addPathPatterns("/api/**")
    .excludePathPatterns("/api/user/login", "/api/user/register", "/api/upload/**", "/api/admin/**", "/api/music/**");
```
登录、注册、上传、管理端接口、音乐接口不需要验证 Token。

### Q9：MyBatis 是怎么工作的？

**答：** MyBatis 是 ORM 框架，把 Java 对象和数据库表映射起来。分三层：
1. **Mapper 接口**（Java 接口）：定义方法，如 `selectById(Long id)`
2. **Mapper XML**（SQL 映射文件）：写具体的 SQL 语句
3. **Service 层**：调用 Mapper 方法，写业务逻辑

比如查询用户：Controller 调用 `userService.getUserInfo(userId)` → Service 调用 `userMapper.selectById(userId)` → XML 中写 `SELECT * FROM user WHERE id = #{id}`。

---

### Q10：事务是怎么处理的？

**答：** 在 Service 方法上加 `@Transactional` 注解。比如创建订单时，需要扣库存、扣心动币、生成订单，这些操作要么全部成功，要么全部回滚。如果中途出错，数据库会自动回滚到操作前的状态。

---

### Q11：心动币体系是怎么实现的？

**答：** 通过 `DailyRewardService` 实现。核心逻辑：
1. 用户执行某个操作（登录、发帖、点赞等）时调用 `grantReward(userId, rewardType, amount)`
2. 方法先查 `daily_reward` 表，看今天这个用户这个类型的奖励是否已领取
3. 如果已领取，返回 0（不重复发）
4. 如果没领取，插入一条记录到 `daily_reward` 表，然后给用户的 `coin_balance` 加钱

这样保证每种奖励每天只能领一次（确认收货除外，无限制）。

---

### Q12：订单流程是怎么走的？

**答：** 完整流程：
1. **创建订单**：前端传商品ID、数量、地址ID、规格 → 后端扣库存、扣心动币、生成订单
2. **待发货**：管理员在管理端发货，填快递公司和单号
3. **已发货/派送中**：管理员更新快递状态
4. **已签收**：用户确认收货，获得 5 个心动币
5. **取消订单**：待发货状态可取消，退还心动币和库存
6. **申请退款**：已发货状态可申请，管理端审核

---

### Q13：前端请求封装做了什么？

**答：** 小程序的 `request.js` 封装了：
1. 自动从本地存储取 Token，放到请求头
2. 响应中如果有新 Token（后端自动刷新的），自动更新本地存储
3. 返回 401 时自动清除 Token 并跳转登录页
4. 返回 403 且 banned 时提示封号
5. 统一错误提示

管理端的 `request.js` 类似，用 axios 拦截器实现。

---

### Q14：管理端的路由守卫是怎么做的？

**答：** 在 `router/index.js` 中用 `router.beforeEach`：
```javascript
router.beforeEach((to, from, next) => {
  const token = localStorage.getItem('adminToken')
  if (to.meta.requiresAuth !== false && !token) {
    next('/login')  // 没 Token 跳转登录
  } else if (to.path === '/login' && token) {
    next('/')  // 有 Token 访问登录页跳转首页
  } else {
    next()
  }
})
```
每个路由配置了 `meta: { requiresAuth: true/false }` 来控制是否需要登录。

## 三、功能设计类问题

### Q15：日记的公开/私有功能怎么实现的？

**答：** `diary` 表有 `is_public` 字段（0=私有，1=公开）。
- 写日记时可以选择是否公开
- 编辑日记时可以修改公开状态
- 别人在情绪分享页点击用户头像，后端调用 `getPublicDiaries(userId)` 只查 `is_public = 1` 的日记
- 自己的日记列表不受影响，全部都能看到

---

### Q16：留言板和抱抱功能怎么实现的？

**答：** 
- **留言**：用户在他人资料页输入文字，调用 `/api/message/send` 接口，写入 `user_message` 表，同时发送通知
- **抱抱**：点击抱抱按钮，调用 `/api/message/hug` 接口，后端从 `healing_quote` 表随机取一条 hug 类型的暖评，作为留言内容写入 `user_message` 表，同时发送通知

暖评词库有 8 条预设的暖心话语。

---

### Q17：音乐功能怎么实现的？

**答：** 
- 数据库 `music` 表存储音乐信息（歌曲名、歌手、类型、文件URL）
- 管理端上传音乐文件到服务器，记录到数据库
- 小程序端点击音乐图标，弹出选择菜单（纯音乐/流行音乐）
- 选择后后端随机返回一首音乐的 URL
- 前端用 `wx.createInnerAudioContext()` 播放音乐，图标旋转动画

---

### Q18：帖子申诉机制怎么实现的？

**答：** 
1. 用户删除自己的帖子 → 进入回收站（`post_trash` 表）
2. 被管理员删除的帖子 → 用户可以提交申诉（`post_appeal` 表）
3. 管理端帖子管理有"申诉管理"标签页，管理员审核
4. 审核通过 → 帖子恢复；不通过 → 只能彻底删除

---

### Q19：每日奖励的时效性怎么保证？

**答：** `daily_reward` 表记录了每个用户每种奖励的领取日期。`grantReward` 方法用 `LocalDate.now()` 获取今天日期，查询今天是否已领取。第二天日期变了，查询结果为空，就可以重新领取。不需要定时任务，是懒加载的方式——用户操作时才检查。

## 四、项目难点类问题

### Q20：开发中遇到的最大问题是什么？

**答：** 主要有几个：
1. **外键约束导致删除用户失败**：address、cart、order 表有外键关联 user 表，直接删除会报错。解决方案是先按依赖顺序删除关联数据，再删除用户
2. **订单规格不显示**：直接购买时 `selectedSpec` 被硬编码为 null，没有从前端参数中取值。修复后从请求参数中提取规格信息
3. **日记标题被挤压**：Flex 布局中内容太多会把标题挤没。用 `flex-shrink: 0` 固定标题宽度
4. **管理端多条 SQL 执行报错**：MyBatis 不支持一个标签里用分号分隔多条 SQL，拆成多个 delete 标签逐个调用

---

### Q21：如果用户量大了，系统会有什么问题？怎么优化？

**答：** 可能的问题和优化方向：
1. **数据库压力**：帖子列表没做分页，数据多了会慢。可以加分页查询
2. **Token 安全**：JWT 密钥存在配置文件里，生产环境应该用环境变量
3. **图片存储**：当前图片存在服务器本地，应该用 OSS 云存储
4. **并发问题**：心动币扣减没有加锁，高并发可能超扣。可以用数据库乐观锁或 Redis 分布式锁

## 六、代码细节类问题

### Q25：`@RequestAttribute("userId")` 是怎么拿到用户 ID 的？

**答：** 在 `JwtInterceptor` 的 `preHandle` 方法中，解析 Token 拿到 userId 后，调用 `request.setAttribute("userId", userId)` 存到请求属性里。Controller 方法参数用 `@RequestAttribute("userId") Long userId` 就能自动取到。

---

### Q26：统一返回结果 `Result` 类是怎么设计的？

**答：** 一个泛型类，包含三个字段：
```java
public class Result<T> {
    private Integer code;    // 200成功, 500错误, 401未登录
    private String message;  // 提示信息
    private T data;          // 返回数据
}
```
提供静态方法：`Result.success(data)`、`Result.error(message)`，Controller 直接调用，不用每次 new 对象。

---

### Q27：跨域问题怎么解决的？

**答：** 在 `WebMvcConfig` 中配置了 CORS：
```java
registry.addMapping("/**")
    .allowedOriginPatterns("*")
    .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
    .allowedHeaders("*")
    .allowCredentials(true);
```
允许所有来源、所有方法、所有请求头，支持携带凭证。

---

### Q28：文件上传怎么实现的？

**答：** 后端 `UploadController` 接收文件，保存到服务器的 `uploads/` 目录，返回文件 URL。前端用 `wx.uploadFile` 上传图片，拿到 URL 后存到日记/帖子的 images 字段。管理端用 Element Plus 的 `el-upload` 组件上传。

`WebMvcConfig` 中配置了静态资源映射：
```java
registry.addResourceHandler("/uploads/**")
    .addResourceLocations("file:uploads/");
```
这样访问 `/uploads/xxx.png` 就能读到服务器上的文件。

### Q30：管理端添加轮播图、商品、删除帖子等操作，小程序端怎么实时显示？

**答：** 系统不是实时推送，而是**请求-响应**模式。管理端操作直接修改数据库，小程序每次打开页面或下拉刷新时重新请求后端，后端从数据库读取最新数据返回。

具体流程：
```
管理员添加轮播图 → 写入 MySQL banner 表
                        ↓
用户打开小程序首页 → wx.request 请求 /api/home/banners
                        ↓
后端从 banner 表查询 is_active=1 的数据 → 返回 JSON
                        ↓
小程序渲染最新轮播图
```

| 场景 | 同步方式 |
|------|----------|
| 添加轮播图 | 用户下次打开首页或刷新时自动显示 |
| 添加商品 | 用户进入"情绪周边"页时自动显示 |
| 删除帖子 | 用户下次进入帖子列表时已看不到 |
| 封禁用户 | 用户下次操作时拦截器检测到 banned 状态，拒绝请求 |
| 修改商品库存/价格 | 用户下次进入商品详情页看到最新信息 |

**为什么不需要 WebSocket？** 小程序的使用场景不需要毫秒级实时性，和微信朋友圈、微博的机制一样——你发了一条动态，别人刷新才能看到。

**如果追问"怎么实现真正的实时推送"？**
1. **WebSocket**：后端和小程序建立长连接，管理端操作后主动推送
2. **定时轮询**：小程序每隔几秒请求一次（浪费资源，不推荐）
3. **消息队列**：用 RabbitMQ/Kafka，管理端操作后发消息，小程序端监听

当前项目用的是最简单也最实用的方案——**每次页面加载时请求最新数据**。

## 七、微信小程序专项问题

### Q32：小程序的生命周期有哪些？

**答：** 分两种：

**应用生命周期（App）：**
- `onLaunch`：小程序初始化时触发，全局只触发一次
- `onShow`：小程序启动或从后台进入前台时触发
- `onHide`：小程序从前台进入后台时触发

**页面生命周期（Page）：**
- `onLoad`：页面加载时触发，只触发一次，可以获取页面参数
- `onShow`：页面显示时触发（每次切换到这个页面都会触发）
- `onReady`：页面初次渲染完成时触发
- `onHide`：页面隐藏时触发（切换到其他页面或进入后台）
- `onUnload`：页面卸载时触发（关闭页面）

---

### Q33：app.json 的作用是什么？

**答：** `app.json` 是小程序的全局配置文件，主要配置：
- `pages`：注册所有页面路径（必须）
- `window`：全局窗口表现（导航栏颜色、标题等）
- `tabBar`：底部 Tab 栏配置
- `sitemapLocation`：sitemap 配置

本项目 app.json 注册了 28 个页面，配置了 4 个 TabBar（首页、情绪分享、情绪周边、我的）。

### Q35：小程序的本地存储怎么用？

**答：** 小程序提供 `wx.setStorageSync` 和 `wx.getStorageSync` 进行本地存储，类似浏览器的 localStorage。

本项目的使用场景：
```javascript
// 登录成功后存 Token
wx.setStorageSync('token', token)
wx.setStorageSync('userInfo', userInfo)

// 请求时读取
const token = wx.getStorageSync('token')

// 退出登录时清除
wx.removeStorageSync('token')
wx.removeStorageSync('userInfo')
```

存储上限是 10MB，适合存 Token、用户信息等少量数据，不适合存大量数据。

### Q36：小程序的页面跳转方式有哪些？

**答：** 主要有 5 种：

| 方法 | 说明 | 本项目使用场景 |
|------|------|----------------|
| `wx.navigateTo` | 保留当前页，跳转到新页面（可返回） | 进入日记编辑页、商品详情页 |
| `wx.redirectTo` | 关闭当前页，跳转到新页面（不可返回） | 登录成功后跳转首页 |
| `wx.switchTab` | 跳转到 TabBar 页面 | Tab 切换 |
| `wx.reLaunch` | 关闭所有页面，打开某个页面 | Token 过期跳转登录页 |
| `wx.navigateBack` | 返回上一页 | 保存日记后返回 |

### Q37：WXML 和 HTML 有什么区别？

**答：**

| 对比 | HTML | WXML |
|------|------|------|
| 标签 | `div`、`span`、`p` 等 | `view`、`text`、`image` 等 |
| 数据绑定 | 需要手动操作 DOM | `{{变量名}}` 自动绑定 |
| 条件渲染 | 需要 JS 控制 | `wx:if`、`wx:elif`、`wx:else` |
| 列表渲染 | 需要 JS 循环 | `wx:for`、`wx:key` |
| 事件绑定 | `onclick` | `bindtap`、`bindinput` |
| 组件 | 自定义组件复杂 | 内置组件丰富（swiper、scroll-view 等） |

### Q38：WXSS 和 CSS 有什么区别？

**答：** WXSS 基本兼容 CSS，但有一些区别：
- 新增尺寸单位 `rpx`（responsive pixel），可以根据屏幕宽度自适应，750rpx = 屏幕宽度
- 不支持大部分 CSS 选择器（如 `*`、`+`、`>`、`~`）
- 样式是局部的，每个页面的样式只作用于当前页面（类似 scoped）
- 可以用 `@import` 引入外部样式

本项目大量使用 `rpx` 单位实现不同屏幕尺寸的适配。

### Q39：小程序的数据绑定机制是什么？

**答：** 小程序采用**数据驱动视图**的模式。数据存在 Page 的 `data` 中，通过 `{{}}` 语法绑定到 WXML。修改数据必须用 `this.setData()`，不能直接修改 `this.data`。

```javascript
// 正确
this.setData({ count: this.data.count + 1 })

// 错误（视图不会更新）
this.data.count = this.data.count + 1
```

`setData` 会把数据从逻辑层发送到视图层，触发页面重新渲染。

### Q40：小程序的事件处理怎么做？

**答：** 在 WXML 中用 `bind` 或 `catch` 绑定事件：
- `bindtap`：点击事件（会冒泡）
- `catchtap`：点击事件（阻止冒泡）
- `bindinput`：输入事件
- `bindchange`：值改变事件

事件处理函数中通过 `e.currentTarget.dataset` 获取自定义数据：
```html
<view bindtap="onDelete" data-id="{{item.id}}">删除</view>
```
```javascript
onDelete(e) {
  const id = e.currentTarget.dataset.id
}
```

### Q41：小程序的组件化开发是怎么做的？

**答：** 小程序支持自定义组件，每个组件由 4 个文件组成：`.json`（声明是组件）、`.wxml`（模板）、`.wxss`（样式）、`.js`（逻辑）。

### Q43：小程序的双线程模型是什么？

**答：** 小程序有两个线程：
- **逻辑层（AppService）**：运行 JS 代码，处理业务逻辑
- **渲染层（WebView）**：渲染 WXML 和 WXSS

两个线程通过微信客户端（Native）进行通信。逻辑层不能直接操作 DOM，必须通过 `setData` 把数据传给渲染层。这样做的好处是逻辑层和渲染层互不阻塞，性能更好。

### Q45：小程序的登录流程是怎样的？

**答：** 微信官方登录流程：
1. 前端调用 `wx.login()` 获取临时登录凭证 `code`

3. 后端用 `code` + `appid` + `secret` 调用微信接口换取 `openid` 和 `session_key`

5. 前端存 Token，后续请求携带

本项目因为是在开发环境，第 3 步做了 Mock 实现（用 code 模拟 openid），实际部署时需要配置真实的 AppID 和 AppSecret。

### Q49：globalData 是什么？

### Q52：小程序的 `onShow` 和 `onLoad` 有什么区别？什么时候用哪个？

### Q54：今日锦囊的翻转动画怎么实现的？

**答：** 用 CSS 3D 翻转实现。核心原理：

1. **父容器**设置 `perspective: 1000rpx`（透视距离，产生 3D 效果）
2. **正面和背面**两个 `view` 绝对定位重叠，都设置 `backface-visibility: hidden`（背面不可见）
3. **背面**初始状态 `transform: rotateY(180deg)`（已经翻过去了）
4. **点击时**通过 `setData` 切换 `quoteFlipped` 变量，给父容器加/删 `flipped` 类名
5. **flipped 状态下**：正面 `rotateY(-180deg)` 翻走，背面 `rotateY(0deg)` 翻过来

```css
.tip-card { perspective: 1000rpx; }
.tip-front { backface-visibility: hidden; transition: all 0.6s ease-in-out; }
.tip-back { backface-visibility: hidden; transform: rotateY(180deg); transition: all 0.6s ease-in-out; }
.tip-card.flipped .tip-front { transform: rotateY(-180deg); }
.tip-card.flipped .tip-back { transform: rotateY(0deg); }
```

点击时 JS 只需要一行：`this.setData({ quoteFlipped: !this.data.quoteFlipped })`

### Q55：锦囊翻转后背景的星光闪烁动画怎么实现的？

**答：** 纯 CSS 动画。在锦囊背面放了 5 个 `view` 作为星星，每个星星是一个白色小圆点：

```css
.star {
  width: 6rpx; height: 6rpx;
  background: #FFFFFF;
  border-radius: 50%;
  animation: twinkle 2s ease-in-out infinite;
}

@keyframes twinkle {
  0%, 100% { opacity: 0.3; transform: scale(0.8); }
  50% { opacity: 1; transform: scale(1.5); box-shadow: 0 0 16rpx 4rpx rgba(255,255,255,0.8); }
}
```

5 个星星分布在不同位置，通过 `animation-delay` 错开闪烁时间（0s、0.4s、0.8s、1.2s、1.6s），形成此起彼伏的闪烁效果。

### Q56：首页日记列表不会因为日记数量越多而无限扩张，怎么实现的？

**答：** 通过固定高度 + 内部滚动实现：

```css
.diary-list {
  height: 480rpx;        /* 固定高度 */
  overflow-y: auto;      /* 超出部分可滚动 */
  -webkit-overflow-scrolling: touch;  /* iOS 平滑滚动 */
  flex-shrink: 0;        /* 不被压缩 */

```

整个页面用 `flex` 布局，每个区域（横幅、轮播图、锦囊、日记列表、输入框）都设了固定高度和 `flex-shrink: 0`，所以日记列表区域不会挤压其他区域，也不会被其他区域挤压。日记内容多了就在 480rpx 的区域内滚动。

### Q58：情绪分享页-发布帖子和点赞、评论，前后端怎么实现的？

### Q59：通知功能怎么实现的？包括管理端赠送心动币、删帖、订单状态通知，以及小红点怎么实现？

### Q60：音乐怎么实现播放的？播放后图标旋转动画怎么实现的？

**答：**

**音乐播放：**
1. 点击"我的"页面音乐图标 → 弹出选择菜单（纯音乐/流行音乐）
2. 选择类型 → 调用 `GET /api/music/random?type=pure`（或 `type=pop&singer=周杰伦`）
3. 后端从 `music` 表随机返回一首音乐的 `fileUrl`
4. 前端用 `wx.createInnerAudioContext()` 创建音频播放器：
   ```javascript
   this.audioContext = wx.createInnerAudioContext()
   this.audioContext.src = music.fileUrl
   this.audioContext.play()
   ```
5. 播放结束时 `onEnded` 回调，停止旋转动画
6. 页面隐藏时 `pause()`，显示时 `play()` 恢复播放

**图标旋转动画：**
```css
.music-icon.playing {
  animation: rotate 3s linear infinite;
}

@keyframes rotate {
  from { transform: rotate(0deg); }
  to { transform: rotate(360deg); }
}
```

通过 `setData({ isPlaying: true })` 给图标加上 `playing` 类名，触发 CSS 旋转动画。停止播放时去掉类名，动画停止。
